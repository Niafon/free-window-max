# API и воспроизводимая проверка

Контракт: `openapi.json` (OpenAPI 3.0.3), интерактивный `/docs`. Базовый адрес локально `http://localhost:3000`, VPS пока не задан. `DATA-API.yaml` содержит последовательные проверки, роли, статусы и обязательные поля. Его версия `1.0` — версия конфигурации проекта, не объявленный организаторами официальный стандарт (точную схему они не приложили).

Все даты ISO 8601 с часовым поясом. Для повторяемой проверки `TEST_DATE` — завтрашняя дата Москвы. Ответы JSON, ошибки `{ "error": { "code", "message", "retryable" } }`. Некорректный ввод 400, нет авторизации 401, недостаточно прав 403, не найдено 404, конфликт состояния 409, истечение компании 410, лимит 429, источник недоступен 503.

MAX: заголовок `X-Max-Init-Data` с **полной неизменённой подписанной строкой** Bridge. Браузер без MAX: `POST /api/v1/auth/guest` (тело `{}` или `{ "name": "Аня" }`) выдаёт подписанную HttpOnly cookie `okno_guest` на 30 дней; веб-клиент вызывает его сам при первом 401, пользователь ничего не вводит. Для проверки ролей сохранить cookie отдельно для каждой роли. Кодов доступа и паролей нет. Админская роль отсутствует: для сценария она не нужна.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health`, `/api/v1/config` | Состояние и открытая конфигурация без ключей |
| POST | `/api/v1/auth/guest` | Автоматическая гостевая сессия для браузера без MAX |
| GET / PUT | `/api/v1/me`, `/api/v1/me/interests` | Профиль, сохранение интересов |
| POST / GET | `/api/v1/search`, `/api/v1/search/:id` | Подбор, чтение собственного демоподбора |
| POST / GET | `/api/v1/sessions`, `/api/v1/sessions/:id` | Компания и статусы |
| GET | `/api/v1/invites/:id` | Обезличенное приглашение |
| POST | `/api/v1/sessions/:id/join` | Присоединение, до 5 человек |
| PUT | `/api/v1/sessions/:id/preferences` | Личные ограничения |
| POST | `/api/v1/sessions/:id/search` | Общий подбор |
| POST | `/api/v1/plans`, `/api/v1/sessions/:id/select` | Сохранение собственного/общего плана |
| GET | `/api/v1/plans/:id` | Карточка по ссылке без личных маршрутов |
| POST | `/api/v1/events/:id/feedback`, `/api/v1/metrics` | Оценка, обезличенное действие |
| GET | `/api/v1/quota` | Внутренний счётчик запросов Яндекс |
| POST | `/max/webhook` | Подписанные обновления MAX |

`dataMode: demo` — тестовые данные (режим интерфейса по умолчанию), не обращается к внешним источникам. `live` — реальные данные; требует Яндекс ключ, возвращает честную ошибку источника/лимита. Live-выдача после перезагрузки возвращает 409: маршруты не сохраняются. Выбор доступен по сохранённому перечню событий, чтение плана не вызывает провайдеры. Неизвестные роли и чужие поиски не получают данных.

Автоматическая проверка DATA-API: `npm run check:api` на работающем локальном сервере. Не содержит платных запросов; создаёт двух участников и тестовый план. Для проверки публичного сервера достаточно выставить `CHECK_BASE_URL`. Конфигурация использует плейсхолдеры и JSONPath-подобные ссылки; встроенный проверяющий скрипт описывает их конкретную семантику.
