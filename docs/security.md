# Безопасность и данные

- `.env`, `private/`, ключи, локальная БД и логи исключены из Git. Секреты отсутствуют в клиентском bundle. `npm run check:secrets` проверяет отслеживаемые файлы на значения локальных секретов.
- MAX initData: HMAC-SHA256 по официальному алгоритму, постоянное время сравнения, контроль возраста и дублирующихся параметров. `initDataUnsafe` не является доказательством личности.
- Webhook: HTTPS, случайный секрет ≥32 символов, `X-Max-Bot-Api-Secret`; повторные update ID отсекаются в БД. При сбое обработки резерв снимается для повторной доставки. Несколько ответов одного диалога не образуют транзакцию внешнего MAX API.
- Браузер без MAX: гостевая сессия создаётся автоматически, без ввода данных. HttpOnly cookie `okno_guest`, SameSite=Lax, Secure на HTTPS, срок 30 дней; содержит случайный идентификатор `guest:…`, имя «Гость NNNN» и срок, подписана HMAC-SHA256 ключом, выведенным из `BOT_TOKEN` (без токена — случайный ключ процесса). Подделать идентификатор MAX-пользователя через неё нельзя: принимаются только `guest:`-идентификаторы. Создание сессий ограничено 10/мин на IP, дневной лимит Яндекса — серверный и общий. `GUEST_AUTH=false` отключает гостевой вход.
- Валидация Zod, лимит тела 32 KB, rate limit, параметризованные SQL, проверка Origin для мутаций и CSP. При VPS приложение доступно только Caddy, доверяет одному proxy hop.
- Чужой поиск закрыт; компания требует участия; общий подбор и выбор только у владельца. Ссылка на маршрут содержит только точку старта запрашивающего участника; сохранённый общий результат не содержит чужой точки в URL. Приглашение раскрывает лишь название и число участников. Участник видит свои параметры и статусы остальных. UUID ссылки на план — разрешение на чтение обезличенной карточки. Публикация ссылки делает эту карточку доступной получателям.
- Геопозиция запрашивается после явного нажатия. Другим участникам точные координаты не отдаются. MAX ID и имя — только для идентификации; телефон не запрашивается.

Хранение: поиски, компании, планы и диалоги до 24 часов; уборка при старте и раз в час. Профиль/интересы — 30 дней без активности; оценки и агрегированные события — 30 дней. Реальные маршруты не сохраняются. Резервные копии содержат персональные данные: на VPS ограничить доступ и выбрать отдельный срок удаления.

Перед публикацией установить случайные пароли БД/webhook, действующий HTTPS, доступ SSH только владельцу. Секреты передавать организаторам отдельно, не через Issues/README/публичный PDF. При утечке перевыпустить соответствующий ключ, не ограничиваться удалением строки из Git.
