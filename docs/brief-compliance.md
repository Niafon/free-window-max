**Внешние шаги перед проверкой:** подключение mini app к боту выполняют организаторы (ссылка передана через их форму), доступ проверяющих и закрытый служебный слайд — владелец. Эти внешние шаги не заменяются наличием Docker-файлов или красивым демо. Пользователь прямо отложил VPS; выдуманного домена или фиктивных результатов проверки нет.

Решения по расхождениям с DOCX: вместо serverless подготовлена VPS по указанию владельца; npm workspaces не нужны для одного приложения с общими пакетами, используется один lockfile; геолокация — браузерная с разрешением; LLM не включена, ручной сценарий полностью независим от неё. Бот использует тестовые данные для точек из списка и реальные для геопозиции; mini app по умолчанию работает на тестовых данных, реальные включаются кнопкой над формой. Желаемые p95 и конверсия остаются целями до пилота.

## Готовность к подключению в MAX (проверено 30.09.2026)

Сверено с актуальной документацией dev.max.ru (Мини-приложения → Общее описание, MAX Bridge, Валидация данных; API → клавиатуры) и с боевым сервером.

| Требование MAX | Как выполнено | Проверка |
|---|---|---|
| URL мини-приложения: только `https://`, латиница, цифры, `.` и `-`, до 1024 символов | `https://77-91-95-175.sslip.io` (корень, без пути) | Сертификат Let's Encrypt, продлевает Caddy; `/health` → `ok` |
| Встраивание в клиенты MAX | CSP `frame-ancestors https://*.max.ru https://max.ru`, без `X-Frame-Options`; скрипт Bridge разрешён в `script-src` | Заголовки боевого сервера |
| Библиотека MAX Bridge | `<script src="https://st.max.ru/js/max-web-app.js">`, `WebApp.ready()` при запуске | `apps/web/index.html`, `App.tsx` |
| Валидация `initData` | Строго по алгоритму документации: `split('&')`/`'='`, `decodeURIComponent`, сортировка ключей, `\n`, `HMAC-SHA256(HMAC-SHA256("WebAppData", token), launch_params)` в hex; дубли ключей и `hash` отвергаются | `tests/auth.test.ts`: пример из документации, «+» не превращается в пробел |
| Срок `auth_date` | 1 час — интервал, рекомендованный документацией (`INIT_DATA_MAX_AGE_SECONDS=3600`) | Тест «подпись старше часа отвергается» |
| Диплинки `https://max.ru/<bot>?startapp=<payload>` | Payload `session_<uuid>`, `plan_<uuid>`, `search_<uuid>` — только `A-Z a-z 0-9 _ -`, < 512 символов; читается из `initDataUnsafe.start_param` | `bridge.ts`, приглашения компании |
| Ссылки из мини-приложения | Внешние — `WebApp.openLink` (по клику пользователя), `max.ru` — `WebApp.openMaxLink`, вне MAX — новая вкладка | `bridge.ts` |
| Шеринг | Внутри MAX — `WebApp.shareMaxContent({ text, link })`, иначе диплинк `https://max.ru/:share?text=` | `bridge.ts` |
| Кнопка «Назад» | `BackButton.show/hide/onClick/offClick` закрывает карточку события | `App.tsx` |
| Кнопки бота | `open_app` («Открыть ОКНО» с payload), `link` (Яндекс Карты, «Забронировать», «Позвать друга») — не больше одной такой кнопки в ряду при лимите 3 | `apps/api/src/max/bot.ts` |
| Настройка бота | При каждом запуске сервер сам ставит команды `/start` и `/help`, сверяет имя бота с `BOT_USERNAME`, в режиме webhook подписывает `PUBLIC_URL/max/webhook` с секретом, если подписки нет. Токен берётся только из `.env` сервера | `configureBot`, `tests/bot.test.ts` |
| Webhook | Подпись `X-Max-Bot-Api-Secret` сравнивается за постоянное время; без неё 401 | Проверено на боевом сервере |

## Изменения 30.09.2026 по критериям оценки

**Продуктовая оценка**

| Критерий | Что сделано |
|---|---|
| Пользовательская ценность | Путь «подобрал → выбрал → забронировал» замкнут: у реального события кнопка «Забронировать на сайте события» ведёт на страницу события KudaGo с билетами и регистрацией; в тестовых данных бронирование имитируется и явно подписано «ТЕСТ». Интересы стали фильтром — пользователь получает именно то, что просил |
| UX/UI и удобство | Вход не нужен ни в MAX, ни в браузере. Переключатель тестовых/реальных данных — над формой рядом с плашкой режима. Пустая выдача предлагает проверенные компромиссы, включая «Показать все категории». Исправлены склонения («1 идея», «3 идеи»), наложение стикера в шапке, конфликт «выбрано и исключено одновременно». Разбор фразы понимает дни недели, «без денег», несколько исключений, «не дальше часа», настроение |
| Обоснованность и целостность | Одни и те же фильтры действуют в mini app, боте и API; в реальном режиме квота маршрутов тратится только на события выбранных интересов |
| Масштабирование | Сопоставление категорий KudaGo вынесено в `mapCategories` (категории + теги) — для другого города или источника меняется таблица, а не логика |
| Презентация | Слайд с реальными событиями и фото с боевого сервера; счётчики тестов актуальны |

**Техническая оценка**

| Критерий | Что сделано |
|---|---|
| Работоспособность и полнота | Основной сценарий проходит в браузере и в MAX без входа; e2e покрывают поиск, фильтр интересов, карточку, выбор, оценку и компанию из двух участников |
| Интеграция и обмен данными | KudaGo: исправлены несуществующие категории; ссылка бронирования — проверенное поле `site_url`. MAX: Bridge и валидация сверены с документацией, шеринг и диплинки — штатными методами |
| Стабильность и ошибки | Ошибка источника или лимита предлагает перейти на тестовые данные; истёкшая подпись MAX даёт понятное сообщение; сбой настройки бота не останавливает сервер |
| Архитектура | `bookingUrl` — часть контракта события (`packages/contracts`), провайдеры его заполняют, интерфейс и бот только показывают |
| Безопасность и данные | Токен бота не хранится в репозитории и не передаётся в CI; валидация `initData` по документации, окно `auth_date` 1 час; тестовое бронирование не отправляет данных наружу |
| Документация | README (сценарий, тестовые данные, бронирование), `docs/api.md`, этот раздел; метрика `booking_open` в `/api/v1/stats` |
| Платформенный бонус | Используются возможности MAX сверх минимума: диплинки с payload для приглашения в компанию, `shareMaxContent`, `BackButton`, уведомления участникам в чате, кнопки `open_app` и `link` с бронированием |
