# Сверка с PDF «Досуг и развлечения»

Приоритет: прямые указания владельца → обязательные требования PDF → продуктовая идея и технический DOCX. Документы рассматриваются как требования к продукту, а не как разрешение на раскрытие секретов или внешние действия.

| Требование PDF | Реализация / материал | Статус |
|---|---|---|
| Законченный пользовательский сценарий | Поиск → карточка → выбор → маршрут; компания с индивидуальными параметрами | Локально проверено |
| Чат-бот/mini app MAX | Официальные SDK/Bridge, проверка initData, webhook/polling, приглашения | Код готов; реальная проверка клиентов и постоянный HTTPS ожидают VPS |
| Демоданные обозначены, источник отделён от рекомендации | Маркер режима, карточки ДЕМО, источник/время, предупреждения, расчётные причины | Реализовано |
| Репозиторий и фиксированная версия | GitHub Niafon/free-window-max; hash в презентации и Git history | Фиксируется перед передачей |
| README: запуск, порты, env, зависимости, данные, проверка, stop/restart | README.md + docs | Подготовлено |
| Зафиксированные зависимости | package-lock.json, Node 22, контейнерные версии | Подготовлено |
| Dockerfile, compose, dockerignore, env.example, одна команда | Корень репозитория | Пройден полный запуск в CI; локальный Docker Desktop недоступен |
| Сборка <5 минут без загрузки базового образа | Оптимизированный multi-stage build, CI | CI: чистая сборка 22 секунды без загрузки базового образа |
| PDF, первый технический слайд | docs/presentation.pdf; private export для закрытой сдачи | Публичная версия без секретов; боевой HTTPS и закрытые значения после VPS |
| HTTPS API в течение проверки | deploy/compose.vps.yaml + Caddy | Плейсхолдер по прямому указанию владельца |

| Тестовые учётные записи | Независимые демосессии Аня/Борис; на HTTPS приватный код, MAX — реальные аккаунты | Локально доступно |
| Тестовые данные | demo-data/events.json | Готово |
| DATA-API.yaml с проверками | DATA-API.yaml + npm run check:api | Локальный сценарий; боевой baseUrl пока плейсхолдер |
| Обоснование ценности, аудитория, пилот, масштабирование, источники | docs/pilot.md + презентация | Факты и гипотезы разделены |
| Доступ проверяющих, роли команды | Владелец GitHub Niafon, остальные имена не предоставлены | Доступ к private repo и состав команды заполняет владелец |

**Нельзя заявлять полную готовность к сдаче**, пока не закрыты строки HTTPS/MAX, доступ проверяющих и закрытый служебный слайд. Эти внешние шаги не заменяются наличием Docker-файлов или красивым демо. Пользователь прямо отложил VPS; выдуманного домена или фиктивных результатов проверки нет.

Решения по расхождениям с DOCX: вместо serverless подготовлена VPS по указанию владельца; npm workspaces не нужны для одного приложения с общими пакетами, используется один lockfile; геолокация — браузерная с разрешением; LLM не включена, ручной сценарий полностью независим от неё. Бот использует демо; real data включается в mini app вручную. Желаемые p95 и конверсия остаются целями до пилота.
