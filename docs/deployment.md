# Будущая VPS: подготовлено, не развёрнуто

Владелец отложил предоставление VPS и домена. `okno.example.com` — **плейсхолдер**, не адрес работающего сервиса. Конфигурация ничего не арендует и не оплачивает. Это явно согласованное изменение первоначального варианта Yandex Serverless из ТЗ.

## Подготовка сервера

Linux x86_64, Docker Engine, Compose ≥2.24.4, SSH, домен с A/AAAA на сервер. Открыть только SSH, 80/443; БД и 3000 наружу закрыты. Первоначальный ориентир 2 vCPU, 2–4 GB RAM, 15 GB диска; окончательный размер после замера. Получить репозиторий на сервер (для private repo read-only deploy key).

1. Скопировать `deploy/vps.env.example` в `.env` в корне репозитория.
2. Указать `APP_DOMAIN`, `PUBLIC_URL=https://<домен>`, `ACME_EMAIL`, имя бота. Сгенерировать разные случайные 32-byte hex строки для пароля БД и webhook. Не оставлять значения `REPLACE_...`.
3. Приватно перенести `BOT_TOKEN` и `YANDEX_MAPS_KEY` из локального `.env`; не отправлять через Git. `chmod 600 .env`. `DEMO_AUTH=false` по умолчанию.
4. Для демонстрации жюри при необходимости разрешить `DEMO_AUTH=true` и случайный `DEMO_ACCESS_KEY` ≥24 символов. Сообщить код только проверяющим.
5. Запустить все компоненты одной командой:

```sh
docker compose -f compose.yaml -f deploy/compose.vps.yaml up -d --build
```

Caddy получает сертификат и проксирует на приложение. Успех: `https://<домен>/health` возвращает `{"status":"ok","database":"ready"}`, интерфейс открывается, `/docs` доступен. Время первичной выдачи сертификата не является временем сборки.

## MAX

В кабинете управления ботом подключить мини-приложение к **корню HTTPS-домена**. Проверить, что бот с именем из `BOT_USERNAME` соответствует токену. В `.env` установить `MAX_MODE=webhook`, заполнить `MAX_WEBHOOK_SECRET`.

Регистрацию webhook выполнить с локального доверенного компьютера, где `.env` содержит **боевой** `PUBLIC_URL` и такой же секрет: `npm run max:webhook`. Скрипт вызывает официальный `POST /subscriptions` с URL `/max/webhook` и обновлениями bot_started/message_created/message_callback. Не включать polling одновременно с подпиской. Не оставлять локальный `.env` с боевым PUBLIC_URL для обычного локального демо — используйте отдельную приватную копию.

Для локального чат-бота без VPS можно установить `MAX_MODE=polling` в `.env` и запустить `npm start`. Подписок webhook при этом быть не должно. Кнопка mini app появляется только с HTTPS PUBLIC_URL; polling не делает localhost доступным внутри MAX. Локальный чат работает пока компьютер и процесс включены.

## Финальная приёмка

Пройти README-сценарии в двух реальных MAX аккаунтах на мобильном и веб-клиенте. Проверить подпись initData, кнопку приложения, приглашение, совместный выбор, внешние ссылки и возврат из карточки. Эмуляция мобильного браузера не заменяет эти шаги.

В `DATA-API.yaml` заменить `baseUrl` реальным HTTPS. Пересоздать OpenAPI с боевым PUBLIC_URL (`npm run docs:api`), добавить commit в служебный слайд. Собрать закрытый PDF `python scripts/build-presentation.py --private`; он включает секреты из `.env`, поэтому хранится только в `private/` и передаётся отдельно. Публичный PDF остаётся без секретов.

В GitHub Actions полный стек уже проверен, чистая сборка заняла 22 секунды без загрузки базового образа. На целевой VPS подтвердить этот результат после прогрева базовых образов: `time docker compose build --no-cache app`. Требование брифа — менее 5 минут; если не выполнено, оптимизировать и повторить до фиксации релиза. Указать фактический результат в `docs/VALIDATION.md`.

## Эксплуатация

Везде использовать ту же пару `-f compose.yaml -f deploy/compose.vps.yaml`. Остановка: `stop`; запуск: `up -d`; логи: `logs --tail 100 app caddy`; обновление: checkout проверенного commit и `up -d --build`. Не публиковать новые изменения после установленного организаторами дедлайна без разрешённого этапа.

Резервная копия: `docker compose exec -T db pg_dump -U okno okno > backup.sql` в закрытом каталоге вне Git. Проверить восстановление на отдельной БД до пилота. Не применять `down -v` к серверу с нужными данными. При смене пароля PostgreSQL существующий volume не переинициализируется: обновление пользователя выполняется отдельной миграцией администратора.

Контроль: `/health`, место на диске, ошибки 5xx, длительность поиска, квота Яндекса, срок сертификата и резервные копии. Доступ SSH и к кабинетам провайдеров остаётся у владельца. Доступ организаторов к приватному репозиторию выдать заранее.
